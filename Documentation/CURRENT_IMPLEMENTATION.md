# Current Implementation

Last synchronized: 2026-07-15.

## Implemented

- Rust 2024 Cargo workspace containing `sim-core`, `sim-config`, `sim-headless`, and `sim-viewer`.
- Engine-independent `sim-core` configuration, deterministic tick counter, pause/reset/speed commands, and immutable `SimulationSnapshot` output.
- Constant-time `Engine`/`World` construction with a declared configurable bootstrap rectangle centered on `(0, 0)`. The repository configuration targets 4,096 x 4,096 cells (with a 1,024 x 1,024 Rust fallback), but the viewer streams it after window creation instead of allocating it at startup; `sim-headless` explicitly materializes it before ticks. Bootstrap coverage is capped at 16,777,216 cells and supports non-aligned rectangular edges.
- A private, three-tier integer-only generation pipeline in `sim-core/src/worldgen/`. Global analytic fields provide domain-warped tectonic plates, continental/oceanic structure, mountain ranges, basins, finite-envelope latitude/altitude temperature, and upwind moisture. The vertical envelope is one stylized cold-warm-cold band with four alternating wobbled wind bands; neither coordinate axis wraps. No presentation or operating-system dependency enters this pipeline.
- Canonical cross-region drainage: one build-once, seed-keyed 257 x 257 lattice samples the complete finite envelope every 256 cells. Its deterministic priority fill owns basin sink IDs, lake IDs/outlets/spill elevations, accumulated runoff, and downstream topology. Dry nodes below 12,000 moisture contribute no perennial runoff. Visible water is not the threshold frontier of that complete graph: at most 24 spatially separated canonical lake outlets with at least 260,000 flow become explicit river sources, and only their complete routes to ocean or world edge are retained. The four review seeds contain 4-15 sources and 33-144 links rather than thousands of exposed runoff edges. Retained routes keep channel identity, Strahler order, collision-checked curved 32-cell refinement with a straight safe fallback, exact non-crossing joins, and an interpolated non-rising water-surface grade.
- Cached regional refinement: each 4,096-cell region retains its existing 129 x 129 macro/climate lattice at 32-cell steps, samples canonical lake surfaces at identical absolute seam coordinates, and filters the shared skeleton's river segments into its bounds. A process-shared build-once LRU retains at most 64 completed region maps, matching the maximum task window, and never evicts an in-flight build. Preparing a request window materializes the one seed skeleton before regional fan-out, so dependent chunks never trigger per-chunk global solves. Cache residency, request order, and worker count affect cost only.
- Per-chunk synthesis interpolates a 3 x 3 regional lattice, adds roughness-budgeted detail, preserves canonical lake-water classification and surface elevation, and rasterizes each river at its interpolated longitudinal surface rather than forcing mountain water below sea level. Deep-water precedence remains order independent. Wetland requires low macro slope plus a canonical basin edge or the river's 18-cell floodplain; a four-cell low-slope riparian bank can replace qualifying dry sand with soil grassland. The same coherent detail sample boundedly shifts coast/beach, desert, forest, wetland, snowline, and treeline thresholds, creating ecotones without another noise call or stored field. Chunk river/floodplain lookup uses a 13-slot allocation-free fast array for the representative seeds plus an initially empty overflow vector, so unusual accepted seeds cannot panic or silently lose segments.
- `World::generate_chunk_at` remains the normal chunk-generation entry point. `ChunkGenerator` is a validated read-only sampler for developer tooling such as the `render_map` BMP example; its internal worldgen context is not public API.
- `World::climate_at` exposes temperature, compact retained moisture, and prevailing wind for resident cells. Its exact temperature reconstruction samples and interpolates the same four globally aligned 32-cell analytic nodes used during generation, so hover inspection neither stores another per-cell field nor synchronously rebuilds regional drainage/climate caches.
- The release-mode `render_map --review-set` developer workflow produces a canonical 14-view world-quality set under `target/world-quality/` without constructing or mutating authoritative `World` state. Review format 3 covers seeds 1, 7, 42, and 10,001 at full-envelope scale plus fixed regional, positive/negative drainage-seam, coastline, verified lake-fed river-source, river-mouth, mountain, forest-feature, outcrop-feature, and berry-bearing close-up probes. Deterministic TSV output records the source revision, half-open bounds, sample step, image dimensions, semantic sample hash, separate surface/biome counts, feature counts/density, seed roles, and relevant public type layouts; elapsed timing remains console-only.
- Shared `sim-config` TOML loading for `sim-viewer` and `sim-headless`, with explicit validation of initial dimensions.
- `sim-config` build integration copies `config/simulation.toml` beside Cargo binaries under the active profile directory, including `target/debug/config/simulation.toml` and the equivalent release path.
- VS Code launch entries build and run viewer/headless binaries in debug or release mode with the repository configuration and working directory, plus a task for the complete workspace validation gate.
- Sparse deterministic tree, rock, and berry-bush feature records owned by the generated world. Canopy, grove, berry-patch, and outcrop bands reuse the already-computed coherent local-detail sample and combine it with biome, climate, slope, and water proximity to create clearings, clustered vegetation, riparian food access, and stone outside mountain-only terrain without another noise call or stored field. `FeatureKind::base_resource`, `Feature::base_resource`, and `World::base_resource_at` expose immutable four-byte generated food/wood/stone capacity; depletion and other mutable feature state do not exist yet.
- Fixed-step accumulator in `sim-viewer`, separating variable render timing from 60 Hz simulation ticks and capping large frame delays. Worker-produced terrain loads merge only after the event-loop turn's fixed-tick phase; resident coverage is a deterministic materialization cache, not tick-driven domain state.
- Native `winit` window and event lifecycle with redraws capped at 60 Hz while active and suspended when paused and visually unchanged.
- GPU presentation through `wgpu`, using size-checked camera uniforms and instanced terrain, feature, selection, hover, and status rectangles instead of CPU framebuffer rasterization.
- Camera-bounded GPU instance caches with an approximately 128-screen-pixel scale-relative margin and static buffers segmented at 1,000,000 instances. Step-1 close rendering visits exact authoritative cells and features. Coarser power-of-two levels use a viewer-owned cache containing one active summary level per intersecting resident chunk: each block has one dominant-terrain base, at most one minority river/lake/coast/snow/rock/hill detail, and at most one density-scaled majority-kind feature marker. Independent missing chunk summaries build in parallel and enter the deterministic `ChunkCoord` map order; exact clipped bootstrap coverage is preserved. Streamed change bounds invalidate only intersecting summaries, rebuild visible work at a 125 ms cadence, force a final page-completion sync, and advance cache revision without an upload when a changed tile is off-cache.
- Deterministic 64 x 64 generated chunks keyed by signed `ChunkCoord`, with bounded lookup instead of a growing linear patch search. Actual storage distinguishes clipped bootstrap tiles from full expansion tiles, so unloaded configured cells are never exposed and partial bootstrap tiles promote monotonically when expansion reaches their fringe. Initial and streaming generation visit complete drainage-region groups before moving to the next region; each tile keeps sparse features row-major for lookup, while resident iterators use deterministic chunk-coordinate then tile-local order.
- A dedicated persistent world-generation coordinator owns a fixed Rayon computation pool sized to available logical parallelism minus one, with a minimum of one worker. It prepares each bounded request window's shared regional inputs before dependent chunks fan out, keeps at most four tasks per worker active with a hard 64-task cap, computes immutable core-owned chunk loads concurrently, and emits them in the authoritative request order. Only the event-loop thread inserts seed/coverage-validated loads into `sim-core`; an unsent page is retained if its queue is full or disconnected, and a stopped coordinator is explicitly reported in the in-game HUD.
- Large-generation guardrails: 65,536 missing chunks per manual request and a centered 1,048,576-chunk world envelope, plus a 64-message result channel and ordered main-thread insertion in 16-load batches within a 2 ms budget, capped at 64 loads per frame. The spatial envelope is authoritative for bootstrap, direct chunk generation, manual generation, and incoming loads. `C` stops new pool dispatch, drops completed stale payloads, waits for already-running pure chunk work, and preserves terrain already applied by the event loop.
- The viewer performs no visible-area or viewpoint-triggered terrain generation. Startup bootstrap work uses a deterministic 32 x 32 `ChunkPager` beginning with chunks `-16..15` on both axes. After that declared area, only an accepted right-button drag requests missing terrain; camera movement, resize, zoom, and hover do not schedule or cancel generation. Manual work preempts bootstrap work, and generation IDs discard stale preempted results.
- Viewer camera starting at `(0, 0)` with cursor-anchored mouse-wheel zoom from a viewport-derived full-envelope fit to 64x magnification. The repository's 4,096 x 4,096 bootstrap reaches the complete red square at 1/16x of initial fit. Left-button drag clamps the visible viewport to the world where it fits, and maximum zoom-out recenters the complete `[-32,768, 32,768)` boundary.
- Right-button drag selection with a translucent yellow valid preview and red invalid preview for missing-chunk-budget or retained-capacity failures. Selections must start inside the maximum-world envelope and are clipped to it as the pointer moves beyond an edge, so release generates the valid in-bounds rectangle instead of rejecting the complete drag. A new manual preview is available while bootstrap work runs and preempts that background work on release; only active manual work or an unavailable worker prevents a new preview.
- Signed world positions supporting generated patches in negative and positive coordinate space.
- Allocation-free `sim-core` chunk inspection exposing canonical signed chunk coordinates, half-open bounds, compact local coordinates, and unloaded initial, unloaded partial-initial, initial, partial-initial, retained, retained partial-initial, or missing coverage without exposing mutable storage.
- A DPI-scaled in-game HUD replaces dynamic window-title output. It shows run/pause state, speed, simulated time, tick, seed, loaded-chunk count, world revision, generation/worker status, selection validity, and either a compact control guide or hovered world/chunk/local coordinates, coverage, surface, biome, elevation, temperature, moisture, wind, sparse feature kind, and its immutable resource kind/capacity. Unloaded cells remain inspectable. A highlighted loaded cell and color-coded chunk outline remain in the world view when readable.
- The bottom time-square is preserved as a presentation element on a subtle rail and completes one traversal per 60 simulated seconds.
- Keyboard controls: pause/resume, 1x-8x speed selection, cancel active generation, reset, and exit.
- Headless runner accepting `--ticks` and `--seed`.
- Unit tests covering equal-input tick determinism, cache-residency-independent tick progression, pause behavior, reset behavior, lazy bootstrap residency, clipped-edge promotion, seed/coverage-validated worker loads, one-worker and multi-worker ordered-output parity, concurrent regional build sharing, bounded center-out paging, cancellation/preemption/non-lossy queue failure, progressive renderer-cache policy, exact chunk-local read-only visitation, summary residency/step replacement, off-grid canonical river preservation, unaligned feature-density preservation, chunk/world agreement across regional boundaries, cold-cache output independence, skeleton equality across Rayon pool sizes, explicit lake-fed source count/spacing/flow, zero arid runoff, non-rising segment grades, canonical continuation/confluence/outlet and basin identity, exact synthetic Strahler confluences, signed seam crossings, shared regional seam samples, order-independent cross-region chunk output, hydrologic wetland guards, rasterized lake-water/feature exclusion, order-independent graded mountain-river precedence, compact drainage-record sizes, and complete-envelope river/floodplain indexing.
- Repository-local skills for orientation, Rust implementation, living documentation, validation, architecture/code review, and workflow evolution.
- Root agent routing with a mandatory inspect, implement, document, review, and validate lifecycle.
- A checksum manifest that detects any change under immutable `InitialDocumentation/`.

## Not implemented

- Chunk unloading, generator versioning, or chunk persistence; bootstrap and manually generated chunks currently remain in memory until exit.
- Spring-, snowmelt-, or finer-than-256-cell catchment sources, optional major tributaries beyond the selected lake-fed routes, dynamic water flow, erosion, dams/canals, mutable resource depletion/regrowth, or terrain modification. Connected basins, lakes, sparse graded static channels, feature placement, base resource capacities, and presentation summaries remain deterministic derivation rather than dynamic world state.
- Persistent agents, needs, cognition, movement, or event scheduling.
- General-purpose deterministic RNG streams, save/load, snapshots on disk, or replay logs.
- Text, asset, animation, and advanced inspection systems beyond the current GPU rectangle renderer.
- Region-owned simulation workers, parallel simulation phases, networking, or long-term persistence. The implemented generation pool performs only pure terrain derivation and never owns mutable simulation state.
