# Current Architecture

## Runtime boundaries

```text
sim-core
  Owns deterministic simulation time, dense agents, analytical physical needs,
  spatial occupancy, bounded perception/routing, scheduled events, the declared
  terrain source, resident materialization cache, commands, and snapshots.
  Has no windowing or rendering dependency.

sim-headless
  Loads shared configuration and runs sim-core headlessly for a requested number of ticks.

sim-viewer
  Loads shared configuration and owns native windowing, keyboard input, the fixed-step driver,
  camera/hover state, a background generation worker, and wgpu rendering. Reads SimulationSnapshot
  and immutable World data for presentation.
```

## Current contracts

- `sim-core::world` is organized by responsibility without widening the crate API: `world.rs` owns world configuration, compact domain records, chunk residency, and materialization; `world/queries.rs` owns resident physical/resource/climate lookup; and `world/visits.rs` owns deterministic read-only iteration. Large private unit suites live beside their owning modules. `sim-core::lib` remains the only downstream-facing re-export boundary.
- `sim-core::agent` owns the dense authoritative population, compact internal positions, stable IDs, movement generations, initialization validation, read-only `AgentView`, and typed movement outcomes. `sim-core::needs` owns exact analytical hunger, thirst, rest, and exposure state plus read-only views and typed threshold outcomes. `sim-core::sleep` owns compact active sleep intervals, quality, interruption causes, and read-only diagnostics. `sim-core::scheduler` owns movement/need/wake event storage and total ordering. None exposes mutable storage or depends on presentation.
- `sim-core::spatial` owns dynamic one-agent-per-cell occupancy separately from immutable generated `World` data. It groups compact row-major local-cell/`AgentId` entries in signed 64 x 64 buckets and applies checked source-to-target transfers. `sim-core::routing` owns reusable bounded Dijkstra scratch; it reads occupancy and `World::traversal_step` but mutates neither.
- Interactive presentation actions mutate simulation state through `EngineCommand`; viewer worker payloads enter through the explicit, capacity-checked `Engine::apply_world_chunk_loads` boundary.
- Presentation reads engine state through `SimulationSnapshot`.
- `Engine::tick` advances checked integer `SimTime` by one when not paused, drains at most 4,096 events due at or before that time, and reports a deterministic due backlog rather than entering an unbounded same-time chain. An idle tick inspects the heap root and does not scan the population.
- Viewer wall-clock time is accumulated and converted into fixed simulation ticks. Worker terrain arrivals merge only after that event-loop turn's fixed-tick phase.
- Rendered objects are temporary views and are not persistent simulation entities.
- `Engine::new` constructs a declared, empty bootstrap world in constant time. `World::generate` and `Engine::materialize_initial_area` remain explicit eager paths; `sim-headless` uses the latter before ticks, while the viewer streams bootstrap tiles after its window and GPU are ready.
- `Engine::new` also constructs an empty population and scheduler. `Engine::initialize_population` is the only Slice 0 spawn boundary: callers provide a nonempty fixed active rectangle, total population, and optionally ordered explicit positions. The complete rectangle must already be resident. Explicit positions receive the first zero-based IDs; missing positions fill from standable cells in row-major world-coordinate order. All validation and allocation complete in temporary storage before the population, scheduler, or IDs become authoritative. The active rectangle is immutable until reset and every move target must remain inside it.
- `AgentId(u32)` is the dense slot identity and is not repeated in the six-byte `AgentRecord`. The finite `[-32,768, 32,768)` envelope permits lossless checked conversion to private `i16` coordinates. A parallel generation value owns lazy movement cancellation; an event is current only when its agent is moving and its generation matches. Reset clears population, active rectangle, scheduler, outcomes, sequence, and time so reinitialization restarts IDs at zero; deterministic terrain residency remains retained under the existing reset contract.
- `ScheduledEvent` remains 32 bytes and the initial scheduler is a standard-library binary heap. Its complete minimum key is `(due SimTime, event-class rank, AgentId, event-detail rank, monotonic sequence)`: need thresholds precede wake, action completion, movement, and decision; same-agent needs rank hunger, thirst, rest, then exposure. Movement completion time is `now + TraversalStep::cost()` with checked `u64` arithmetic. Rescheduling inserts a new generation and leaves the old record harmlessly stale; movement and route scheduling filter stale entries after retained heap state reaches current population work plus 4,096 (minimum 64). This is the measured 20-100-agent implementation behind a private API that can later adopt bucketed scheduling without changing event identity or ordering.
- Each agent owns one parallel 32-byte `NeedState`, leaving the six-byte hot position/activity record unchanged. Four 0-10,000 visible values use signed rates per 60 fixed ticks, one shared reference time/generation, and per-need sub-unit remainders so rebasing is exact. Current values saturate through integer arithmetic and are never written per tick. Population initialization schedules hunger, thirst, and rest crossings; neutral exposure has no event. An activity/rate change rebases once, advances the shared wrapping need generation under a retained-event bound far below `u32::MAX`, and predicts only future positive-rate crossings with ceiling division. A reached threshold emits one outcome and remains crossed until later state moves below it. Route waypoints remain one moving activity; only route start/end changes rates. Global sequence exhaustion settles a due mover idle without moving and reports a typed failure. `Engine::physical_needs` and `Engine::need_threshold_outcomes` are read-only inspection boundaries; resource, shelter, health, and death consequences remain later slices.
- Each agent also owns one parallel 12-byte `PolicyState`, one three-byte food/wood/stone inventory, and one 24-byte `SleepState` outside the hot position/activity record. Explicit activation schedules decisions; initialization alone does not. A decision reads the analytical need view, inventory, and bounded objective perception, then schedules one route/action/sleep/build commitment or one positive delayed reconsideration. Gather/eat/drink/build completions revalidate objective state and apply atomically at the ordered action boundary. Sleep validates the current agent-owned resident standable cell, rebases to a quality-selected analytical rate profile, and retains only start time, one planned wake, quality, and an active flag. Open ground uses rest/exposure rates `-8/+2`; cardinal access to a completed shelter uses `-12/-4`. One checked policy generation invalidates superseded decisions, action completions, and wakes, while movement and need generations retain their existing ownership. Reached needs may atomically interrupt a build with full material refund or interrupt sleep before an equal-time wake, rebase idle, record the cause, and schedule at most one next decision. Policy activation makes the engine the sole commitment owner for that population; public manual move/route/sleep/build requests are rejected as `PolicyControlled` until reset. Current public policy, sleep, and structure diagnostics are latest-tick observations, not persistent simulation truth.
- Population initialization builds occupancy in the same temporary publication boundary as agent records. Moving agents remain present at their source until their scheduled completion. The scheduler's existing `AgentId` tie-break performs completion-time collision arbitration: the first event transfers atomically, later events observe the occupied target and do not change either position or index. Request-time checks reject targets already occupied but never reserve an empty target, avoiding caller-order-dependent winners.
- `Engine::perceive_physical` accepts a radius through 31, clips it to the immutable active rectangle, and emits objective agent, fresh-water, composed available-resource, sparse structure, and traversable-cell facts in global row-major order. Available resources are immutable generated base capacity minus the engine's sparse changed-feature remainder. `Engine` owns a separate sparse shelter store: monotonic `StructureId`, fixed lifecycle records, row-major footprint lookup, and builder lookup while construction is active. Structure footprints are never written to `World`; perception removes them from traversable cells. `Engine::request_route` uses cardinal minimum-travel-time Dijkstra with a caller budget capped at 4,096 expansions. The only retained per-agent route data is optional compact destination plus budget; one reusable engine planner keeps node, lookup, and frontier capacities across searches. Direct movement, route search, and movement completion all consult structure footprints, closing the reservation-versus-in-flight-move race. Routes progress through positive traversal-cost events rather than tick polling.
- `WorldConfig` defines validated bootstrap dimensions, defaulting to 1,024 x 1,024 cells. The rectangle is centered on the world origin and is a deterministic loading target, not a claim that every cell is resident. Its 16,777,216-cell safety limit permits non-64-aligned rectangles within the separate maximum world envelope.
- World storage is a deterministic `BTreeMap` materialization cache of private loaded tiles. A bootstrap tile holds exactly its intersection with the configured rectangle; an expansion tile holds a complete 64 x 64 chunk. `World::cell`, visitors, feature queries, and `loaded_bounds_at` expose only resident coverage. The seed/configuration define terrain independently of that coverage, and current simulation state must not branch on cache residency. A partial bootstrap tile promotes monotonically to a full expansion tile if a later request reaches its fringe.
- Generation visits 64 x 64 chunks, while `World::cell` exposes coordinate lookup without presentation dependencies. `ChunkCoord::from_world_position`, `ChunkCoord::bounds`, and `World::inspect_chunk_at` provide the same Euclidean signed-coordinate rules to inspection clients and distinguish unloaded initial, unloaded partial-initial, initial, partial-initial, retained, retained partial-initial, and missing chunk footprints.
- Terrain uses dense four-byte `TerrainCell` values. Elevation and quantized moisture occupy three bytes; a private one-byte `TerrainClass` packs `SurfaceType` in its low nibble and `BiomeType` in its high nibble. Public typed accessors expose semantics without allowing arbitrary packed values. Traversal, fertility, and settlement rules must derive from these meanings and other world inputs until measurement justifies stored flags. Trees, rocks, and berry bushes use sparse 24-byte `Feature` records rather than per-cell object slots. Their four-byte `BaseResource` values are derived on demand and are not retained beside each feature. Resident cell/feature iterators are deterministic by `ChunkCoord` (`x`, then `y`) and tile-local row order; they do not promise global world-row order for sparse coverage.
- Terrain generation is private to `sim-core` and uses integer-only absolute coordinates in three tiers. Analytic plate, coast, relief, temperature, and moisture fields are pure functions of the seed and coordinates. Temperature uses the finite vertical envelope as one non-periodic cold-warm-cold band; four 16,384-cell circulation bands alternate prevailing direction with noise-displaced boundaries, and neither world axis wraps. A seed-keyed `DrainageSkeleton` then samples the complete `[-32,768, 32,768]` boundary lattice every 256 cells, priority-fills it serially from ocean/world-edge sinks, routes accumulated runoff in stable fill order while rejecting already-selected crossing diagonals, labels canonical basin sinks and water bodies, and records lake outlets/spill elevations or terminal status. Moisture at or below 12,000 produces no perennial runoff. Visible rivers are selected separately: qualifying nonterminal lake outlets are ranked deterministically, kept at least 2,048 cells apart, capped at 24 for the complete envelope, and traced through the canonical graph to ocean or world edge. Their merged routes receive stable channel identity and Strahler order.
- `DrainageSkeleton` lives behind a four-completed-seed build-once `Mutex`/`OnceLock` LRU. Its retained state is immutable filled-surface/lake-depth arrays plus compact lake, source, channel, and 32-cell-subdivided river records; elevation, moisture, fill, target, accumulation, and traversal scratch are released after construction. Each refined link has exact canonical endpoints, bounded perpendicular curvature and small interior detail, plus `u16` start/end water surfaces that never rise downstream. In-flight seeds are never evicted. `prepare_chunk_regions` materializes the seed skeleton before parallel regional preparation, so chunks do not perform global solves and concurrent callers share one result.
- Each 4,096-cell `RegionMap` keeps the existing 129 x 129 elevation, temperature, moisture, roughness, and water-depth arrays. Water depth is computed from the skeleton's bilinear filled surface and the region's absolute-coordinate elevation; shared edge nodes therefore agree exactly without coordinate-based dry margins. The region filters the same global river geometry into both sides of a crossed edge. Region maps retain their separate 64-completed-entry LRU, and cache presence, pool size, generation order, and completion order affect cost only.
- Final chunk synthesis interpolates a 3 x 3 node window, applies bounded local detail, preserves lake identity and surface elevation, and rasterizes overlapping river cores/banks using depth precedence rather than segment iteration order. A river cell receives the segment-projected longitudinal water surface, so an upland river remains upland and descends toward its destination instead of being assigned a global below-sea-level constant. Deep water wins over shallow water wherever contributors overlap, while a canonical lake remains a lake when a channel crosses it. Land becomes wetland only when low macro slope and a canonical basin-edge transition or river floodplain coincide with saturated warm/temperate lowland limits; a narrower four-cell riparian band creates qualifying soil-backed banks. The existing coherent detail value displaces classification thresholds within fixed numeric bands. Feature synthesis reuses that value as bounded canopy, grove, berry-patch, and outcrop bands, then combines it with biome/climate eligibility, macro slope, and basin/river proximity. Water, sand, and snow/ice cells cannot emit sparse surface features.
- Each 64 x 64 generation chunk has a 13-slot stream/floodplain influence fast path proven allocation-free over every chunk in the finite envelope for seeds 1, 7, 42, and 10,001. An initially empty overflow vector handles any unusual accepted seed beyond that measured capacity without a panic or discarded channel. The internal `ChunkContext` is not public. Tooling that needs sparse sampling uses the validated `ChunkGenerator` contract instead of raw origin/span inputs.
- The `sim-core` `render_map` example is a read-only derived-output client of `ChunkGenerator`. Its 14-view format-3 review set never inserts generated chunks into a `World`; BMP pixels, terrain/feature distributions, type layouts, manifests, and stable semantic hashes are developer evidence rather than simulation truth. Full-resolution forest, outcrop, and berry-bearing probes make local feature patches and record-density accounting visible. Canonical views are bounded by `WORLD_GENERATION_BOUNDS`, and sample alignment is relative to each view's minimum coordinate across signed chunk boundaries.
- `sim-viewer::camera::Camera` owns presentation-only center and zoom state. `CameraView` caches the per-frame transform used for screen/world conversion. Visible bounds are half-open: the minimum floors the top-left world point and the maximum ceils the bottom-right point so fractional edge cells are included without adding a cell at exact integer edges.
- Mouse-wheel zoom preserves the world point under the cursor until viewport clamping is required. Its minimum zoom is derived from the ratio between configured-bootstrap fit and complete-world fit, so maximum zoom-out encloses the full square on any window aspect ratio. Left-button dragging clamps the visible viewport to the maximum world where that viewport fits; if a viewport is larger than the world on an axis, that axis is centered.
- Camera space uses floating-point presentation coordinates and may move into negative or otherwise ungenerated locations; `World` lookup still returns only resident core-owned terrain cache entries.
- `EngineCommand::GenerateWorldArea` exposes area generation as an `Engine` command path; `WorldRect` uses signed inclusive-minimum/exclusive-maximum coordinates. The viewer's right-drag does not use this path — it streams chunks through a dedicated worker (see below).
- Generated selections use deterministic signed `ChunkCoord` tiles inside the half-open `[-32,768, 32,768)` square. The viewer only begins a right drag inside that envelope and intersects its presentation-owned selection with the envelope, so crossing an edge caps the preview and release request at the last valid cells. Chunk traversal groups complete 4,096-cell drainage regions before moving to the next region, preventing a wide request from repeatedly evicting the 64-entry regional cache. Manual selection remains all-or-nothing at 65,536 missing chunks; the spatial envelope contains exactly 1,048,576 chunks and is checked before iteration. Duplicate/stale payloads are idempotent, and a payload must match both the receiving world seed and its declared bootstrap coverage.
- `World::feature_at` uses binary search over each tile's row-major sparse features for bounded hover lookup without a global scan. A generated feature's world position is its stable identity within a seed and eventual generator version. `World::base_resource_at` derives the feature's immutable `BaseResource`: 12 food units for a berry bush, 120 wood for a tree, or 80 stone for a rock. `Engine` now owns a sparse `BTreeMap` from compact feature position to changed `u16` remaining capacity; zero remains as one permanent Phase 2 depletion record, while unmodified features retain no mutable state. Regrowth timing, damage, fire, and ownership remain future simulation-owned layers; presentation state may never supply those values.
- Physical simulation must use the explicit resident-query boundary rather than interpret `None` from presentation-oriented inspection. `World::standability_at` validates dry, non-tree, non-rock resident spawn cells; `World::resource_at` returns resident absence separately from `WorldQueryError::Unloaded`/`OutsideWorldBounds`; `World::water_at` returns ocean/lake/river identity with drinkability derived from that type; and `World::traversal_step` accepts exactly one cardinal cell, reads two resident cells plus the target sparse feature, and returns a compact derived cost/block reason without invoking generation caches. Current walking blocks all water, elevation deltas above 512, and tree/rock target cells. Settlement policy composes these primitives outside `sim-core`; no suitability score or per-cell traversal flag is authoritative terrain state.
- `World::climate_at` returns a four-byte read-only `ClimateSample` only for resident cells. It reconstructs exact classification temperature from four aligned 32-cell analytic nodes, reuses the cell's quantized moisture byte, and derives prevailing wind directly; it does not allocate, retain another cell field, or touch the regional/drainage caches.
- `World::visit_cells_in`, `visit_cells_in_step`, and `visit_features_in` bound general presentation extraction to a camera rectangle. `visit_loaded_regions_in` enumerates exact clipped/full resident chunk coverage in deterministic key order; `visit_cells_in_chunk` and `visit_features_in_chunk` then read one known chunk without rescanning the complete chunk map. These are immutable inspection contracts only and never expose storage or make residency authoritative simulation state.
- Manual selection and background bootstrap share one persistent viewer coordinator. Manual right-drag work has priority over bootstrap. The bootstrap `ChunkPager` yields one deterministic center-out 32 x 32 chunk page at a time and retains only its current ring state. The coordinator owns a fixed Rayon pool of `available_parallelism - 1` workers, with a one-worker minimum. Before dependent chunks fan out, it prepares the next bounded request window's distinct regional maps through the same pool, preventing workers from parking behind a cold `OnceLock`. Its active-plus-completed reorder window is four tasks per worker capped at 64; immutable loads may finish out of order, but the coordinator releases only the next original request index through the separate 64-message result channel. Manual preemption cancels active bootstrap work by generation ID: no new tasks are dispatched, completed stale results are dropped, already-running pure tasks finish, and already-applied chunks remain valid. The main thread inserts 16-load batches while a 2 ms budget remains, with a hard 64-load per-frame ceiling. A full or disconnected job queue returns the unsent page for retry/retention; a stopped coordinator becomes HUD-visible and prevents further requests. Camera movement, resize, and zoom never schedule or cancel generation.
- `C` cancels remaining work, drops the bootstrap pager and pending manual work, and preserves already applied chunks. Bootstrap does not restart afterward, but a later accepted right-drag selection can queue manual work. Manual requests that exceed coordinate, per-request, or expansion-capacity guardrails are reported rather than weakened.
- Every applied streamed batch unions its exact loaded bounds into presentation dirtiness. The renderer invalidates only summary chunks intersecting those authoritative bounds, rebuilds a visible affected cache at most once per 125 ms during streaming, rebuilds immediately when camera coverage or summary level changes, and advances its revision without a GPU upload for off-cache changes. Page completion requests a final immediate synchronization.
- The viewer enforces a persistent 60 Hz redraw deadline while simulation, generation, or coalesced GPU synchronization is active and stops redrawing when paused and visually unchanged. Input, resize, ticks, surface recovery, and streamed arrivals mark presentation dirty.
- The `wgpu` renderer keeps camera transforms in 32-byte uniforms and terrain/features in 20-byte rectangle instances. A scale-relative cache margin of approximately 128 screen pixels prevents buffer uploads during ordinary pans. Step 1 renders exact authoritative cells/features; each coarser power-of-two level retains only one viewer-owned `ChunkRenderSummary` per resident chunk intersecting that margin. A summary block draws one dominant ordinary terrain base, then at most one bounded minority detail prioritized as river, lake, mixed coastline, snow, rock, or hill. It draws at most one feature marker whose kind is the deterministic local majority and whose area increases with total feature density. Missing summaries build independently in parallel and are inserted into a `BTreeMap` in stable `ChunkCoord` order; changing level clears the former level rather than retaining a full pyramid. Static instance uploads remain split at 1,000,000 instances per GPU buffer. The cursor chunk and maximum-world border each use four bounded overlay rectangles; the ten-instance world-overlay staging vector is reused across frames. A separate fixed-capacity screen-overlay vector renders the DPI-scaled HUD, built-in 5 x 7 bitmap glyph runs, and bottom time rail/square without adding a font dependency or persistent simulation state.

## Dependencies

- `sim-core`: Rust standard library and Rayon. Rayon is confined to pure indexed regional derivation and exposes no scheduler or mutable cache handle.
- `sim-config`: `sim-core`, `serde`, and `toml`; owns filesystem and TOML concerns shared by runtime binaries.
- The `sim-config` build script tracks the repository configuration and copies it into the active Cargo profile directory so directly launched binaries retain the default `config/simulation.toml` layout.
- `sim-headless`: `sim-config` and `sim-core`.
- `sim-viewer`: `sim-config`, `sim-core`, `winit`, `wgpu`, `pollster`, `bytemuck`, and Rayon. Rayon is confined to immutable terrain payload computation; it never mutates `Engine` or presentation state.
